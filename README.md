# Golf Trip Records

A clean, static site for the annual golf trip: a home page with the trip lineup,
a players page, and an all-time leaderboard. No build step, no framework — just
HTML, CSS, and vanilla JS reading from JSON data files. Hosts on GitHub Pages.

## Structure

```
index.html          Home — hero for the next trip + trip lineup + stats
players.html        Players — card grid of every crew member
leaderboard.html    All-time leaderboard — sortable stats table
css/style.css       All styling
js/core.js          Data loading, score parsing, stat aggregation, nav/footer
js/home.js          Home page rendering
js/players.js       Players page rendering
js/leaderboard.js   Leaderboard rendering + sorting
data/
  tournaments.json  Played events (generated by parse.py from CSV exports)
  upcoming.json     Not-yet-played trips (edit by hand)
  players.json      Official Ryder Cup records (edit by hand)
raw/                Original CSV exports (source of truth for parse.py)
parse.py            Converts raw CSV exports -> data/tournaments.json
```

## Adding a new trip each year

1. Drop the new tournament CSV export into `raw/`.
2. Run the parser:  `python3 parse.py`
   This regenerates `data/tournaments.json` from every CSV in `raw/`.
3. Move the trip out of `data/upcoming.json` (delete that entry) and add next
   year's trip there instead.
4. Update `data/players.json` with the new Ryder Cup records.
5. Commit and push. GitHub Pages redeploys automatically.

The parser handles the crew's Golf Genius export format: it reads the Players,
Strokeplay (gross + net), Ryder Cup, Best Ball, and Skins sections, and ignores
any practice-round Strokeplay table (one where only Round 1 is filled).

### Name matching

If a player's name is spelled differently across years (e.g. "Freddie" vs
"Fred"), add the mapping to `NAME_ALIASES` at the top of `parse.py` so their
stats merge into one person.

## Naming the crew

The crew has no name yet, so the nav shows the flagstick mark alone. To add a
name later, set `SITE.name` at the top of `js/core.js` — it will appear next to
the mark automatically.

## Previewing locally

The pages load data with `fetch`, which browsers block over `file://`. To
preview, run a local server from this folder:

```
python3 -m http.server 8000
```

Then open http://localhost:8000 . On GitHub Pages (served over https) it just
works — no server needed.

## Deploying to GitHub Pages

1. Push this folder to a GitHub repo.
2. Repo Settings → Pages → Source: deploy from branch, `main`, `/ (root)`.
3. Your site goes live at `https://<user>.github.io/<repo>/`.

The `.nojekyll` file tells Pages to serve everything as-is.
